# 雲端家人 Daily Nudge — Setup & Deploy

**Built:** 2026-06-21 · **Decisions baked in:** **host one-tap LINE forward** (no bot, no setup for anyone) · **07:00 host-local** send time · daily push **on by default** for family · **one-tap Amen** feedback.

This is the implementation of the design doc (`DESIGN_雲端家人_每日連結觸及_2026-06-21.md`). The default delivery model needs **zero setup from hosts or members**: the host gets a morning notification and forwards the verse into the family's LINE group with one tap. (A fully-automatic LINE-group bot is available as an *optional, advanced* add-on — see the last section.)

---

## What it does (the daily loop)

Every hour, a GitHub Actions cron wakes up. For each Cloud Family where it is **now 7am in the host's timezone** and today's nudge hasn't gone out yet, it:

1. Looks up **today's verse** from the team's reading schedule (same day-index logic the app uses).
2. **Sends the host a "share with your family" push.** Tapping it opens LINE's native share sheet with the verse pre-filled (via LINE's `line.me/R/share` scheme) — the host picks the family group and sends. No bot, no group setup.
3. **Also nudges any members who enabled push directly** (the daily push is on by default for family), so they get today's reading + the one-tap **Amen / 已讀** even before the host forwards.
4. Marks the team sent so a second run in the 7am hour doesn't double-send.

The forwarded message carries a `/fc` card URL that renders a verse preview in LINE, then redirects the human into the app deep link (which credits today's reading and offers Amen).

> **Optional (advanced):** if a host binds the family's LINE group to the VerseRain bot, the cron *auto-posts* into the group and skips the host-forward prompt entirely. Most families won't need this.

## Deploy steps

### 1. PartyKit backend (the new endpoints)
```bash
npx partykit deploy
```
Confirm the room env already has `ADMIN_TOKEN` (or `PARTYKIT_ADMIN_TOKEN`) set — the cron uses it to read `/teams/daily-feed`. It's the same token that guards `/push-subscriptions`, so it already exists.

### 2. Frontend (Vercel)
Push to your deploy branch; Vercel builds `api/family-card.js`, ships `public/og-family.png`, and applies the `/fc` rewrite automatically. Verify after deploy:
```
https://www.verserain.com/fc?team=t_demo&set=ps37&i=0&ref=Ps%2037:4&t=Delight%20yourself&title=Psalm%2037&amen=1
```
Paste that into a LINE chat with yourself — you should see a verse card.

### 3. GitHub Actions secrets (the cron)
Repo → Settings → Secrets and variables → Actions → add:

| Secret | Value |
|---|---|
| `PARTY_BASE` | `https://verserain-party.hungry4grace.partykit.dev/parties/main/global-auth-db` |
| `ADMIN_TOKEN` | same value as the PartyKit `ADMIN_TOKEN` |
| `VAPID_PUBLIC_KEY` | the public key in `src/pushConfig.js` |
| `VAPID_PRIVATE_KEY` | the matching private key (**reuse the one your existing daily-verse cron already uses**) |
| `VAPID_SUBJECT` | `mailto:hungry4grace@gmail.com` |
| `PUBLIC_ORIGIN` | `https://www.verserain.com` |
| `LINE_CHANNEL_ACCESS_TOKEN` | *(optional — see LINE section)* |

### 4. Test before going live
GitHub → Actions → **Cloud Family daily nudge** → *Run workflow* → check **dry_run**. Read the logs: it lists each team and what it *would* send. Then run again with **force** checked to actually push once, regardless of the hour.

## LINE group auto-posting — OPTIONAL / ADVANCED (most families can skip this)

**You do not need any of this for the default experience.** By default the host forwards the daily verse into the family group with one tap — no bot, no account, nothing to install. This section is only for power users who want the verse to post into the group **fully automatically**, with no daily tap.

It requires a LINE bot (Messaging API). I built the bot's logic — an **auto-binder webhook** (`api/line-webhook.js`) — so once the bot exists, a group is linked just by typing the family's invite code in the chat. **No hunting for a "group ID."** If you set this up once for the whole app, individual hosts only do the trivial "add bot + type invite code" step (or skip it and use the default forward).

The steps below split into "only you can do this" (your LINE account) and "already built."

### Part A — what only you can do (one-time, ~10 min, needs your LINE login)

1. **Create a Messaging API channel** at <https://developers.line.biz/console/>. Sign in with your LINE account, create a Provider (e.g. "VerseRain"), then a **Messaging API channel** (this is your Official Account). You must accept LINE's developer terms — that's why I can't do this part for you.
2. In the channel's **Messaging API** tab:
   - Issue a **Channel access token (long-lived)** → copy it.
   - Note the **Channel secret** (Basic settings tab).
   - Turn **Use webhook = ON**, and set the **Webhook URL** to:
     `https://www.verserain.com/api/line-webhook`
   - Under "LINE Official Account features", **disable Auto-reply / Greeting messages** (so only our bot replies).
3. Add these to your secrets:
   - **GitHub Actions secrets** (for the cron): `LINE_CHANNEL_ACCESS_TOKEN`.
   - **Vercel env vars** (for the webhook): `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_CHANNEL_SECRET`, `ADMIN_TOKEN`, and `PARTY_BASE` (same values as elsewhere in this doc).
4. **Invite the bot** (your Official Account) into your family's LINE group, like adding any friend.
5. In that group, **type your family's invite code** (e.g. `IZ2-5HAF`, or `綁定 IZ2-5HAF`). The bot replies `✅ 已連結雲端家人「…」` — the group is now linked.

That's it. The next 7am run posts the day's verse into the group automatically.

### Part B — already built and tested (no action needed)

- `api/line-webhook.js` — receives LINE events, verifies the signature, and on an invite code auto-binds the group to that family (calls the admin-only `POST /teams/set-line`), then confirms in chat. Ordinary chatter and 1:1 messages are ignored.
- `POST /teams/set-line` (PartyKit, admin-token) — resolves the family by invite code and stores the `groupId`.
- The cron already posts to any team that has a bound group; teams without one simply skip LINE and still get Web Push.

> Manual fallback (if you ever want to bind without the chat command):
> ```bash
> curl -X POST "$PARTY_BASE/teams/set-line" \
>   -H "Content-Type: application/json" -H "x-admin-token: $ADMIN_TOKEN" \
>   -d '{"inviteCode":"IZ2-5HAF","groupId":"Cxxxxxxxx"}'
> ```
> Optional: set a fixed send timezone per team with a `/teams/update` call adding `"settings":{"timezone":"Asia/Taipei"}`. Otherwise the host's timezone is auto-detected from their device.

## Notes & tuning

- **Double notifications:** members who also enabled the *personal* daily-verse push will get two morning pushes (personal + family). If that's noisy, we can suppress the personal one for family members — say the word.
- **iOS Web Push** only works when VerseRain is added to the Home Screen (PWA) — this is an Apple limitation, already handled by the existing onboarding. LINE group posts have no such limit, which is another reason LINE is the stronger channel here.
- **Host timezone** comes from the host's device at the time they turned on push; the `settings.timezone` override above is the escape hatch.
- **Verification done:** a 52-assertion integration test (`node test-family-daily.mjs`) drives 10 pseudo users through the **real** PartyKit `Server` class over HTTP — including the host one-tap LINE-forward push, member read-nudges, and the optional bound-group auto-post — family create/join, schedule, daily-feed, Amen, the live cron sender, date-window logic, idempotency, the OG card, `set-line`, and the LINE webhook auto-binder — all green. A full `vite build` couldn't run in my sandbox because `node_modules` holds your macOS native binaries — please run `npm run build` locally once before deploying as a final check.
